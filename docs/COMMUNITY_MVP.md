原生入口：“我的 → 公开资料 / 互动消息 / 我的收藏 / 我的公开主页”，以及校园顶部消息按钮、作者头像、帖子详情收藏按钮。

“我的”展示公开昵称和头像，学校姓名单独保留在仅自己可见的学籍卡片。使用本机头像需要主动选择，并确认公开范围后才上传、保存，不自动公开学号、成绩、课表或学校照片。

沿用现有液态玻璃和页面组件，未修改底部导航数量。覆盖小屏、大字体与主题回归；Apple Design 技能主要影响了触控区域、即时反馈、可读性和公开资料确认流程。

## 服务端

代码同时修改了相邻的 `cuit-ratings-api` 仓库，没有操作生产服务器或数据库。

- 复用 `rating_profiles` 和现有校园 JWT，不建立第二套登录；新增资料版本与头像资源引用。
- 新增 `006_community.sql`，包含个人消息、私有收藏、写入限流，以及头像退役时间字段；迁移已加入执行清单。
- 资料采用版本校验，头像校验归属、绑定状态、大小、实际编码及尺寸，对外返回头像时移除原照片 EXIF 等元数据。
- 新头像绑定与资料更新在同一事务；旧头像立即停止对外访问，物理清理保留等待期，不清理仍被资料引用的图片。
- 回复与消息在同一事务提交；不通知自己，同一回复对同一接收者只生成一条消息，失败与重试不产生虚假或重复通知。
- 全部已读采用服务端字符串水位，防止清掉快照之后的新消息；个人消息不套用匿名公告缓存规则。
- 收藏添加/删除幂等，只有本人能查询；删除、隐藏的目标不返回旧正文或作者，仍允许取消收藏。
- 发帖、编辑、回复、点赞、资料、上传、收藏均有限流；举报和管理隐藏沿用原有机制。
- 应用内消息仍按进入页面、回到前台和手动刷新拉取；Android/iOS 另通过 FCM/APNs 发送论坛回复系统推送。推送失败不影响应用内消息，Web/PWA 和鸿蒙暂不发送系统推送。

## 新增接口

前缀：`/api/v1/ratings/community`，复用现有代理。所有新增接口需要现有校园 JWT，并返回 `Cache-Control: no-store`。

| 方法、路径 | 作用 |
| --- | --- |
| `GET/PATCH /me/profile` | 本人公开资料；修改要求 `expected_version` |
| `GET /profiles/:id` | 指定公开身份的资料，不返回认证 subject 或学籍字段 |
| `GET /profiles/:id/threads` | 指定作者可见帖子，游标分页 |
| `GET /me/notifications` | 本人消息、未读计数、`read_watermark` |
| `GET /me/notifications/unread` | 可见消息未读计数 |
| `PUT /me/notifications/:id/read` | 本人单条消息已读 |
| `PUT /me/notifications/read-all` | 按 `{read_watermark: "序号"}` 已读 |
| `POST/DELETE /me/push-devices` | 绑定或解除当前 Android/iOS FCM 设备令牌 |
| `GET /me/favorites` | 本人收藏，游标分页 |
| `GET/PUT/DELETE /me/favorites/forum-threads/:id` | 查询、幂等添加/取消帖子收藏 |

另新增 `GET /api/v1/forum/replies/:id`，定位回复时检查帖子、回复和父回复的可见性。

资料修改传 `display_name`、`avatar_preset`、`avatar_asset_id`、`expected_version`。图片先用现有附件接口上传，再绑定；`avatar_asset_id: null` 表示用预设头像。昵称 2–24 个用户感知字符；头像限 2 MB、4096×4096，且须为有效单帧 JPG/PNG。

## 验证结果

2026-10-20：

- Flutter 静态分析通过，347 项测试通过。
- Web lint、类型检查、414 项测试、生产构建和原有 OTA 打包通过；生成本地包不等于发布。
- 服务端类型检查、构建、163 项测试通过，包含隔离的本机 MySQL 9.3 迁移、真实 HTTP/JWT、并发和权限验证。
- 新增测试覆盖头像归属与 EXIF 移除、资料版本冲突、通知去重与事务回滚、已读水位、跨账号游标、隐藏内容、收藏幂等及迟到响应隔离。
- 界面测试覆盖公开资料确认/取消/保存、320px 小屏、放大字体及实际应用跨栏目跳转返回；已检查深浅色预览，未替代真机相册、网络、主题及冷启动验证。

独立数据库测试通过 `COMMUNITY_TEST_MYSQL_PORT`、`FORUM_TEST_MYSQL_PORT`、`ANNOUNCEMENTS_TEST_MYSQL_PORT` 显式指定本机临时实例。测试创建随机数据库，不读取生产 `.env`，不要将端口指向生产实例。

## 发布前仍需做

1. 分别整理两个仓库的改动，保留其他任务已有的未提交工作，不混入无关文件。
2. 备份生产数据库，在与生产一致的 MySQL 8 环境演练 `006_community`，确认 DDL 耗时、权限与恢复方案。
3. 先发布兼容服务端与迁移，再发客户端。旧客户端保留旧字段回退，新客户端遇到旧服务端会提示尚未上线。
4. Android/iOS 双账号真机验收：相册权限、深浅色、安全区、冷启动、导航连续点击、回复定位、弱网、退出与重新登录。
5. 核对源码、服务端、基础包、补丁与下载入口的版本对应关系；Flutter CI 仍需补齐，不能以已有 Web/旧封装流水线替代。
6. 小范围体验后再扩大开放；屏蔽/拉黑、账号数据处理、社区规则与运营响应仍需继续完善，不宣称完整治理体系已建成。

回退优先关闭新入口或回退服务/客户端版本，不通过删除新增表来丢弃已产生的用户资料、消息和收藏。
